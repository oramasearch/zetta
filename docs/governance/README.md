# Governance docs

Governed self-serve: **deny-by-default, key-scoped access** (a request inherits the scope +
capabilities of the key it logged in with, RULE-3) and an **immutable, retained audit trail** for
every governed action — the two controls every surface (deploy, run, console, cloud burst) enforces
through. Read here when adding any action a user can take: it must be capability-checked at the boundary
and recorded as an `AuditEvent`. The read-only GUI is [../gui/admin-panel.md](../gui/admin-panel.md);
the gate that governs *correctness* (vs access) is [../pipeline/gate.md](../pipeline/gate.md).

- [access-control.md](access-control.md) — key-scoped access (V1): `Principal` + `AccessKey` + `Scope` (resources) + `Capability` (rights, TTL'd), deny-by-default (RULE-3 / ENT-22). Plus the **credential store** (#744): `User` + `Role` + `Token` (hashed at rest) + `UserRole`, and the bootstrap owner (#733); the **default-deny gate** (#745, always on since #799 — no auth flag/toggle; `--require-auth` and `ZETTA_REQUIRE_AUTH` were removed); and **RBAC roles** (#746): the permission vocabulary, built-in admin/writer/reader reconciled on bootstrap, custom roles + user↔role assignment via SQL (gated on `roles:manage` and **bounded** by the caller's own rights, built-ins fixed — #761), surfaced in `system.roles` / `system.user_roles`. Blob grants match on a `/` path boundary, not a bare text prefix (#767). Optional Clerk JWTs use coalesced async key retrieval, cached failures, and bounded stale keys (#1416). Connection-owned app credentials compose those entities with table/topic and tool grants (#1280). Run-metric reads use `api:query`; writes are exact orchestration operations included in `pipelines:manage` (#1137). Study promotion and deletion use distinct `studies:promote` and `studies:delete` atoms (#1138, #1158). Running a published pipeline is `serving:run` (`data:run_pipeline`, scopable ON PROJECT) plus the caller's own `sql:read` on what it reads (zetta#1289). **Per-statement SQL enforcement** (#1229): every data-changing statement checks `sql:write` / `sql:ddl` (or `users:manage` / `tokens:manage`) at table or database scope, column grants and row security apply to `UPDATE` / `DELETE`, and each is audited as `data_changed`. A row policy missing the predicate its command enforces (replicated or restored) **denies**, never admits every row (#765).
- [system-catalog-access.md](system-catalog-access.md) — who may read each `system.*` table and the spec index (#766): the trusted local session and `cluster:admin` read everything; otherwise each table is public metadata, a read tool's rows (whoever may call the tool), the datasets the caller may read, the caller's own audit rows, or admin-only. `/v1/specs`, `list_specs` and `get_spec` list only the tools the caller may call.
- [identity-seal.md](identity-seal.md) — **membership is not authority** (#763, #764): every replicated identity record (user, role, token, assignment, row policy, principal, access key) is sealed by the cluster's identity root (Ed25519, derived from the owner's admin token, pinned in `<data_dir>/security/identity-root.json`) and honored only when its seal verifies; a verify-only node issues no identity; the owner is seeded after the join, with ids fixed by the root, so a joining node never mints a second owner.
- [audit-trail.md](audit-trail.md) — immutable `AuditEvent` values, data-bearing polling summaries, independent ordinary/summary retention, admin-only audited purge, per-origin segment replication outside the catalog, all-nodes-together upgrades, compacting legacy migration, and the `data_changed` action for SQL statements that change data, schema or governance, the Node's own `data_changed` rows for project, database, model and run changes, and caller attribution through `AuditActorScope` (ENT-23 / FEAT-9, #1154, #1164, #1169, #1229, #847).
- [egress-policy.md](egress-policy.md) — **outbound network is denied by default** (CTL-4, #75): the node may reach only loopback and an operator-set allowlist (`--egress-allow` / `ZETTA_EGRESS_ALLOW`: hosts, `*.domain`, addresses, CIDR ranges, ports), checked at the one outbound dialler before DNS and on every redirect hop; each refusal is audited as `egress_denied`. Under a Lake, the operator's NetworkSandbox is the enforcer and the engine's allowlist is `*`.
- [../pubsub/crud.md](../pubsub/crud.md) — separate topic/event rights and per-sequence,
  hash-only mutation audit records for node-local pub/sub CRUD (#1136).
- [secret-references.md](secret-references.md) — CTL-3 (#74): a credential zetta replays to an external system is saved by name in the sealed saved-connection store and resolved in memory; an inline credential is used, never kept, and `governance::redact_credentials` keeps it out of the consent challenge (the refusal, `list_consent_requests`). Open: the sealing root secret still lives under `data_dir` (#1314); `DeploymentTarget::credentials_ref` is not resolved yet (#1315).
- [step-authority.md](step-authority.md) — a graph step runs as the run's principal (#843): each step kind names the right it exercises (connect `data:read` or `sql:read ON TABLE`, clean `create_dataset_from_query`, model `train_model`, index `create_index`, serve `data:predict`, act `deliver_action_task`), checked deny-by-default when the step is reached, every decision a `data_access` audit event. Enforced by `GraphExecutor::run_as`, the API `run` / `run_solution` and the governed console.
- [destination-policy.md](destination-policy.md) — where an author-chosen outbound URL may go (#1394, LSR-161): action and report delivery endpoints dial only public addresses, checked on each resolved address and on every redirect hop, with the connection pinned to the checked address; `--action-allow-destinations` / `ZETTA_ACTION_ALLOW_DESTINATIONS` allows `loopback`, `private`, `link-local` or `metadata`.
- [governed-console.md](governed-console.md) — the governed Console/REPL screen: every statement capability-scoped, sim-Python gated before it runs, each statement audited (SCR-8 / #525).
- Remote consent for cloud-touching actions (#621) lives with its surface: [../api/consent.md](../api/consent.md) — `ConsentLedger` (governance) + the challenge/approval protocol (api); approvals must come from a different principal, audited on both sides. **Enforcement is OFF by default (#995)** — a gated capability executes on the first call and the ungated call audits as `consent_bypassed`; `--governance` turns the challenge back on.
