# Churn model validation — 500-account synthetic set (2026-07-25)

**Subject:** `churn_model` (native histogram-GBDT, `binary_logistic`), retrained for the Charles/Motive demo (#862).
**Why:** the built-in 10-account fixture yields **AUC = 1.0 / accuracy = 1.0** — implausibly perfect on 10 rows, and a credibility risk in front of a technical buyer. This retrains on a realistically-sized, noisy set so the metric is believable.

## What was tested

- **Model:** `278d6dcb-f67d-4854-973f-7acaac99311b`, project `charles-churn`, trained via the live churn engine (`run` with `dataset_path`), weights sha256 `608aa9d2…`, 37,143 bytes.
- **Against:** `motive-churn-500` — **500 accounts / 8,354 events / 28.0% churn**, generated by [`scripts/gen_churn_dataset_dir.py`](../../scripts/gen_churn_dataset_dir.py) (stdlib-only, **seed=42**, reproducible). Canonical churn dataset dir (`dataset.json` + `accounts.jsonl` + `events.jsonl`); as-of `2026-03-01`, 90-day horizon; point-in-time featurization windows to `event_ts <= as_of`. Includes the **FedEx TC-4 entity-resolution siblings** (6 divisions sharing `brand="FedEx"`, distinct entities, one churned). Signal is learnable-but-noisy by construction: `payment_failed`/`support_ticket` counts scale with a latent risk (Poisson noise), and the label carries logistic noise, so the classes overlap.

## Measured results

| Metric | 10-row fixture (before) | motive-churn-500 (after) |
|---|---|---|
| **AUC** | 1.000 | **0.880** |
| Accuracy | 1.000 | 0.828 |
| Log loss | 0.015 | 0.402 |

**Driver importances (native TreeSHAP), after:** `failed_payments` **57.4** (dominant) · `support_severity` 34.2 · `mrr` 33.4 · `tenure_days` 22.3 · `total_events` 17.7 · `seats` 17.2 — all meaningful (the fixture model had every driver but `failed_payments`/`total_events` at 0). This matches the generator's design (payment failures the leading churn driver) and gives the demo a believable "what's driving churn" answer.

## Verdict

Credible: **AUC 0.88** on 500 noisy accounts is the realistic operating point a technical buyer expects, and the ranked at-risk list + drivers now come from a model that isn't trivially separable. Use this dataset (`~/.zetta-local/datasets/motive-churn-500`, regenerate with the seeded script) as the demo's churn corpus. Ground-truth signal separation at generation: mean `payment_failed` = 2.54 (churned) vs 1.27 (retained).

Reproduce: `python3 scripts/gen_churn_dataset_dir.py` then `run(project=charles-churn, graph="charles churn graph", dataset_path=<dir>, top_k=20)` → `get_model`.
