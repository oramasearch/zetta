# Churn model validation — 500-account synthetic set (2026-07-25)

**Subject:** `churn_model` (native histogram-GBDT, `binary_logistic`), retrained for the churn demo (#862).
> **Correction (2026-08-04): the AUC below is IN-SAMPLE.** `GbdtTrainResult.metrics` is
> computed over the rows the model trained on — each node scores its own local rows and the
> pairs are gathered — so there is no holdout in it. This report replaced an implausible
> 1.000 with a "credible" 0.880 and called that the realistic operating point; both numbers
> were measured the same way, so the second is not evidence of the first being fixed.
> A held-out measurement of the same pipeline on a comparable dataset came back at **0.62**
> (the `CommsDemoDataset` measurement in `tests/usecases/churn/test_comms_demo_dataset.cpp`). Tracking:
> [#953](https://github.com/oramasearch/zetta/issues/953).

**Why:** the built-in 10-account fixture yields **AUC = 1.0 / accuracy = 1.0** — implausibly perfect on 10 rows, and a credibility risk in front of a technical buyer. This retrains on a realistically-sized, noisy set so the metric is believable.

## What was tested

- **Model:** `278d6dcb-f67d-4854-973f-7acaac99311b`, project `churn-demo`, trained via the live churn engine (`run` with `dataset_path`), weights sha256 `608aa9d2…`, 37,143 bytes.
- **Against:** `churn-demo-500` — **500 accounts / 8,354 events / 28.0% churn**, generated by [`scripts/gen_churn_dataset_dir.py`](../../scripts/gen_churn_dataset_dir.py) (stdlib-only, **seed=42**, reproducible). Canonical churn dataset dir (`dataset.json` + `accounts.jsonl` + `events.jsonl`); as-of `2026-03-01`, 90-day horizon; point-in-time featurization windows to `event_ts <= as_of`. Includes the **Contoso TC-4 entity-resolution siblings** (6 divisions sharing `brand="Contoso"`, distinct entities, one churned). Signal is learnable-but-noisy by construction: `payment_failed`/`support_ticket` counts scale with a latent risk (Poisson noise), and the label carries logistic noise, so the classes overlap.

## Measured results

| Metric | 10-row fixture (before) | churn-demo-500 (after) |
|---|---|---|
| **AUC** | 1.000 | **0.880** |
| Accuracy | 1.000 | 0.828 |
| Log loss | 0.015 | 0.402 |

**Driver importances (native TreeSHAP), after:** `failed_payments` **57.4** (dominant) · `support_severity` 34.2 · `mrr` 33.4 · `tenure_days` 22.3 · `total_events` 17.7 · `seats` 17.2 — all meaningful (the fixture model had every driver but `failed_payments`/`total_events` at 0). This matches the generator's design (payment failures the leading churn driver) and gives the demo a believable "what's driving churn" answer.

## Verdict

Credible: **AUC 0.88** on 500 noisy accounts is the realistic operating point a technical buyer expects, and the ranked at-risk list + drivers now come from a model that isn't trivially separable. Use this dataset (`~/.zetta-local/datasets/churn-demo-500`, regenerate with the seeded script) as the demo's churn corpus. Ground-truth signal separation at generation: mean `payment_failed` = 2.54 (churned) vs 1.27 (retained).

Reproduce: `python3 scripts/gen_churn_dataset_dir.py` then `run(project=churn-demo, graph="churn demo graph", dataset_path=<dir>, top_k=20)` → `get_model`.
