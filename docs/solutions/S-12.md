# S-12 Claims Triage & Fraud Referral

S-12 assigns a first-notice-of-loss claim to `fast_track`,
`adjuster_assignment`, or `siu_referral`. It combines entity resolution (M-2),
native document extraction (M-11), tabular referral-risk scoring (M-1), and,
at levels 3 and 4, segmentation (M-3). The decision policy delivers path tasks
through the shared action outbox. It never authorizes claim denial.

Denial is represented only as `denial_recommendation` with A0 authority. A0
records a human recommendation and cannot enter the connector delivery path.
The correctness gate checks that no score tier selects denial, and the run path
revalidates the current policy version so a later policy edit cannot weaken the
rule.

## Data contract

The caller lands one point-in-time FNOL row per claim and supplies these roles:

| Role | Required | Meaning |
|---|---:|---|
| entity | yes | Stable claim identifier used by the policy, task, ledger, and outcome |
| label | yes | Matured referral or audit disposition used to train M-1 |
| time | yes | FNOL snapshot cutoff and claim-development chronology |
| feature | yes | Pre-decision numeric claim, policy, claimant, provider, and history signals |
| document | yes | FNOL notice or evidence text plus a stable document identifier |
| document label | optional | Verified field values for M-11 precision and recall |
| owner | optional | Adjuster or SIU owner; the configured delivery owner is the fallback |
| fairness cohort | evaluation | Protected cohorts used for review, never model features |

Every decision row must explicitly provide `fnol_complete`,
`coverage_confirmed`, `identity_verified`, `document_confidence_clear`, and
`fairness_review_passed`. Missing or false evidence blocks delivery. A
`catastrophe_override` or `manual_only` flag also blocks model-driven routing.
The caller supplies snapshot, dataset, destination, owner, and ROI economics;
credentials remain write-only run input.

M-1 materializes a claim-specific table in `claims_results` with `claim_id`,
`referral_score`, ranked reasons, and evidence. The solution's default
`decision_source` selects that real child-run output by name. It does not bind
to the churn module's `account` and `risk` columns.

## Levels

| Level | Native stages | Behavior added |
|---:|---|---|
| 1 | M-2, M-11, M-1 | SIU queue ranking, document review routing, governed claim paths, holdout, tasks, ledger, monitor, and readout |
| 2 | level 1 | Human release of all three triage paths with the same native evidence chain |
| 3 | level 2 + M-3 | Claim segments for bounded straight-through-payment eligibility and review |
| 4 | level 3 | The same governed composition for photo and subrogation assistance; denial remains human-only |

All four levels build and run. M-2, M-11, and M-1 are mandatory at every level;
M-3 is mandatory at levels 3 and 4.

## Defaults

Referral scores at or above 0.75 select `siu_referral`; scores at or above 0.40
select `adjuster_assignment`; lower scores select `fast_track`. The three path
actions are A2 and deliver owned tasks. Fast-track work above 5,000 configured
cost units becomes A1 pending approval. `denial_recommendation` is always A0.
The starter execution budget is 100,000 configured cost units, with one path
action per claim and one action per rolling 30-day window. These values are
editable starter settings, not calibrated fraud cutoffs or payment advice.

Every score tier receives an independent, deterministic 10% holdout. Remaining
claims enter `path_assignment` or `referral_task` treatment cells. The default
outcome is `referral_confirmed` over 45 days, measured with a treated-minus-
holdout confidence interval. Guardrails cover automated denials, low-confidence
path assignments, fairness-review failures, field-extraction accuracy, and
action-execution rate.

## Run it

1. Create a project and land the FNOL table.
2. Call `get_solution` with `{"solution":"S-12"}` and select level 1–4.
3. Call `create_solution` with claim-specific M-11 fields and the shared
   foundation inputs:

```json
{
  "project": "claims-triage",
  "solution": "S-12",
  "level": 1,
  "sources": {
    "source": "claims",
    "table": "fnol",
    "M-11": {
      "document_column": "document",
      "document_id_column": "entity_id",
      "labels_column": "document_labels",
      "fields": ["claim_number", "loss_date", "loss_amount"],
      "review_threshold": 0.8
    }
  },
  "foundation": {
    "snapshot": {
      "database": "claims",
      "source_table": "fnol",
      "target_table": "fnol_snapshot",
      "entity_column": "claim_id",
      "time_column": "observed_at",
      "as_of": "2026-09-01T00:00:00.000Z"
    },
    "dataset": {
      "entity_column": "entity_id",
      "label_column": "referral_confirmed",
      "feature_columns": ["claim_amount", "prior_claims"]
    },
    "delivery": {
      "kind": "webhook",
      "endpoint": "https://claims.example.test/tasks",
      "owner": "claims-triage"
    },
    "roi_model": {
      "value_per_outcome": 100,
      "investment": 200,
      "currency": "USD"
    }
  }
}
```

4. Call `run_solution`, poll `get_run`, and read the solution decisions,
   policy, experiment, action tasks, ledger, and monitor.
5. Record `referral_confirmed` against each ledger action. After the outcome
   window closes, call `get_roi_readout` for the measured effect and interval.

Webhook, Salesforce, and HubSpot destinations use the existing retry,
idempotency, acknowledgement, dead-letter, holdout, kill-switch, and audit
paths. Protected holdouts and A0 denial recommendations create explicit
no-action ledger evidence and never reach a connector.

## Correctness checks

`create_solution` and `run_solution` execute the same composed correctness
gate. Each condition below is a refusal:

1. A score tier cannot select denial, and every denial-like action must remain
   A0 human-only.
2. A named owner must require cohort and referral-rate fairness review.
   Protected attributes are evaluation-only and are blocked from model inputs.
3. M-11 must assign confidence, retain source evidence, route uncertain fields
   to review, and use a threshold at or above the governed 0.8 default.
4. Path delivery requires explicit document-confidence evidence.
5. Every level must include M-2, M-11, and M-1; levels 3 and 4 must include M-3.
6. M-1 must publish the real `claim_id` and `referral_score` decision table.

The runtime also rechecks the latest policy before acting. It refuses an edited
policy that selects denial, raises denial above A0, or removes document and
fairness eligibility evidence.

## Boundaries and deferred work

This module adds no new JSON or wire format. It composes existing solution,
policy, experiment, monitor, action, ledger, and ROI schemas. Live lake proof is
recorded after the branch is deployed to the target environment; it cannot be
produced by the repository-local suite.
