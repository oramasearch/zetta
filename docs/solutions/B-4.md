# B-4 Document & Workflow Automation

B-4 extracts declared fields with M-11, keeps field-level confidence and
evidence, sends uncertain fields to an owned human-review queue, and hands
validated structured data to a downstream workflow. It is a runnable solution
module: `create_solution` builds all four capability levels and `run_solution`
executes the snapshot, document extraction, policy, permanent holdout, action
delivery, ledger, monitor, and ROI readout.

Engineering readiness is independent of the catalogue promotion condition.
The condition remains recorded for commercial offering decisions: promote for
a high-volume document lane or repeated demand from multiple deployed modules.

## Data contract

The caller supplies a landed document table and these roles:

| Role | Required | Meaning |
|---|---:|---|
| document | yes | Source text or page image available to M-11 |
| field | yes | Declared field names and a confidence threshold for each |
| label | yes | Verified field values and the named workflow outcome |
| entity | yes | Stable document, case, customer, or transaction key |
| time | yes | Document-arrival time, snapshot cutoff, and outcome cutoff |
| owner | yes | Human-review queue and downstream workflow owner |
| eligibility | yes | Workflow eligibility and suppression evidence |

`sources.M-11` names the document, document ID, labels, fields, and review
threshold. `sources.correctness.field_thresholds` must contain every declared
field. `sources.correctness.review_queue` identifies the owned queue. The
foundation supplies the frozen snapshot, dataset roles, action destination,
owner, and customer economics. Delivery credentials remain write-only Run
input.

## Levels

| Level | Native stages | Behavior added |
|---:|---|---|
| 1 | M-11 | Extract fields, retain confidence/evidence, write validation records, and route uncertain fields to review |
| 2 | M-11 | Add owned workflow-review tasks for validated documents |
| 3 | M-11 | Hand validated structured fields to the configured workflow |
| 4 | M-11 | Require A1 approval before high-impact workflow release |

Each level is built through the registered M-11 callback. The policy action
changes by level; it does not substitute an unrelated classifier.

## Defaults

The policy has a validated tier at confidence 0.9 and a review tier below that
floor. The default fields are `invoice_number`, `date`, and `total`; their
per-field thresholds are 0.9, 0.85, and 0.9. The review threshold must cover
the highest field threshold so every uncertain value enters review.

`field_review_task`, `workflow_review_task`, and `workflow_handoff` are A2.
`high_impact_approval` is A1. Validation records are A0. A policy permits one
action in a rolling 30-day window and requires explicit document availability.
Excluded documents are suppressed. The kill switch is off.

Validated and review tiers each receive a permanent 10% holdout. The named
outcome is `workflow_completed` over 30 days at document grain. The monitor
requires zero unvalidated workflow actions and review-queue misses, minimum
field extraction accuracy 0.8, and minimum action execution rate 0.95. Field
validation rate is recorded for operations review.

## Run it

1. Create a project and land the document table.
2. Call `get_solution` with `{"solution":"B-4"}` and choose level 1–4.
3. Call `create_solution` with the source and foundation contract above.
4. Call `run_solution` with the returned graph and optional delivery token,
   then poll `get_run`.
5. Read the policy with `get_policy`, tier assignments with `get_experiment`,
   the decision table with SQL, actions with `list_ledger`, and guardrails with
   `get_monitor`.
6. Record `workflow_completed` against ledger action IDs after the outcome
   window, then call `get_roi_readout`.

The decision source is M-11's real `extracted fields` output in
`document_results`, using `document` as the entity and `confidence` as the
score. Because M-11 writes one row per field, the foundation groups rows by
document, verifies every required field exactly once, and uses the lowest
per-field confidence for the validation tier. It preserves the extracted
values, confidence map, page and box evidence, and low-confidence field list.

Review deliveries contain the document ID, structured values, confidence and
evidence, low-confidence fields, and queue name. Workflow deliveries use the
same evidence but are refused unless every required field is validated.
Protected holdouts remain in the ledger and receive no external action.

## Correctness checks

`create_solution` and `run_solution` execute the same composed correctness
gate. Each condition below is a refusal:

1. `b4_per_field_confidence` requires one threshold in `(0, 1]` for every
   unique required field, the matching M-11 attributes, confidence output, and
   a review threshold at least as strict as the highest field threshold.
2. `b4_review_queue` requires a named, owned human-review queue, an A2 review
   action, M-11 low-confidence routing, and per-field thresholds on the review
   action stage.
3. `b4_validated_workflow` requires structured-only downstream input, explicit
   all-fields validation, review and workflow actions that differ, and the
   selected level's action policy.

The tests mutate each contract and verify its named refusal. They build levels
1–4 through M-11. The level-3 journey lands synthetic invoices with a planted
low-confidence field population, proves those documents enter review, proves
validated documents alone reach workflow handoff, protects holdouts, and
recovers a planted 0.18 workflow-completion effect inside its confidence
interval.
