# S-1 Churn & Retention

S-1 predicts which customer, account, or household may leave, explains the
prediction with up to three ranked reason codes, and turns the result into a
governed retention decision. It is a runnable solution module: `create_solution`
builds its native methodology pipeline, and `run_solution` executes the
snapshot, models, policy, permanent holdout, action delivery, ledger, monitor,
driver report, and ROI readout.

The decision table includes risk, value, and dominant-driver cells. High-risk
entities can produce an owned CRM task with an SLA. Medium-risk entities can
produce a capped retention-journey trigger. Low-risk entities, protected
holdouts, exclusions, exhausted caps, and negative-uplift profiles receive no
model-driven contact.

## Data contract

The caller supplies a landed source table and these roles:

| Role | Required | Meaning |
|---|---:|---|
| entity | yes | Stable actionable customer, account, or household key |
| label | yes | Churn or retention outcome from a fully observed window |
| time | yes | Feature cutoff, label window, and snapshot observation time |
| feature | yes | Point-in-time behavioral, service, and billing inputs |
| value | yes | Numeric customer value or an explicit value tier |
| treatment | level 3 | Randomized retention treatment and observed outcome |
| owner | for routed tasks | Account owner; otherwise the configured delivery owner is used |
| duration and event | level 2 | Follow-up duration and event indicator for M-5 |
| action candidates | level 4 | Eligible treatments, costs, contact state, and budget inputs for M-8 |

Each action row must carry explicit `in_collections`, `open_complaint`, and
`vulnerable` evidence. Missing or true exclusion evidence blocks contact. The
caller also supplies the snapshot boundary, dataset roles, webhook or CRM
destination, owner, and ROI economics. Credentials remain write-only run input.

## Levels

| Level | Native stages | Behavior added |
|---:|---|---|
| 1 | M-2, M-1, M-3 | Calibrated churn propensity, top-three reasons, risk × value × driver cells, playbook, permanent tier holdout, driver report, and readout |
| 2 | level 1 + M-5 | Censoring-aware survival timing |
| 3 | level 2 + M-6 | Uplift targeting after at least one randomized cycle; non-positive uplift and profiles outside the targeting set are recorded as no contact |
| 4 | level 3 + M-8 | Treatment arbitration under eligibility, contact, and budget constraints |

`get_solution.solution.levels` returns four objects with integer `level`, `name`,
and `description` fields. Pass the selected integer to `create_solution.level`.

## Defaults

The policy starts with high/medium/low score floors of 0.7/0.4/0.0. High risk
selects `csm_task`; medium risk selects `retention_journey`; low risk selects
`no_contact`. Tasks and journeys are A2, have a one-day SLA, and allow at most
one action in a rolling 30-day window. The lifetime contact cap is 12. An
optional discount is A2 through 50 currency units and A1 above that amount.
The per-policy budget is 1,000 currency units and the kill switch is off.

The experiment assigns every entity deterministically and permanently. Each
risk tier has an independent 10% holdout probability. The remaining population
is split between `csm_task` and `retention_journey` treatment cells. Level 3
changes the readout design to uplift cells and preserves no-contact decisions as
observations rather than silently dropping them.

The monitor enforces maximum complaint fraction 0.01, maximum discount budget
1,000, maximum contact-fatigue count 1, and minimum action-execution rate 0.95.
These are editable starter settings, not customer-specific calibration or ROI
claims.

## Run it

1. Create a project and land the source table.
2. Call `get_solution` with `{"solution":"S-1"}` and select an integer level.
3. Call `create_solution` using the request shape in
   [executable-pipelines.md](executable-pipelines.md). Put methodology hints in
   `sources.M-<id>`. Optional gate overrides belong in `sources.correctness`, so
   they are not forwarded to methodology callbacks.
4. Call `run_solution` with the returned graph and optional delivery token, then
   poll `get_run`.
5. Read the decision table from the Run outputs, policy with `get_policy`, cells
   with `get_experiment`, tasks and reports through the action integration
   read-backs, and guardrails with `get_monitor`.
6. Record the named retention outcome against each ledger action. Call
   `get_roi_readout` after the outcome window closes.

Webhook, Salesforce, and HubSpot task delivery use the shared action outbox,
idempotency, retry, acknowledgement, dead-letter, kill-switch, and audit paths.
The task payload carries owner, SLA, tier, action, decision cell, and up to three
reason codes. A webhook run also publishes the driver report through the report
action pattern.

## Correctness checks

`create_solution` and `run_solution` execute the same composed correctness gate.
Each condition below is a refusal, not a warning:

1. Every methodology feature source must be a materialized snapshot at or before
   prediction time T.
2. The label window must begin after the feature window and configured blackout
   gap.
3. Validation must be out of time and stable across at least two rolling windows.
4. A named customer group must remain disjoint between train and test.
5. Propensity labels must be fully observed; level 2 and above must include the
   censoring-aware M-5 head.
6. Sampled training requires disjoint Platt or isotonic calibration.
7. M-2 must resolve one actionable unit and refuse duplicate entities.
8. The configurable leaky-feature blocklist must be nonempty, selected features
   must clear it, and reported AUC above 0.95 stops action for leakage review.

Level checks also require M-5 at level 2, M-6 plus one randomized cycle and
positive-only targeting at level 3, and M-8 at level 4. The tests mutate every
condition and verify its named refusal. The level-1 planted-effect journey runs
build → run → decide → act → record outcomes → readout and recovers the planted
retention effect inside its confidence interval. The level-3 planted-structure
journey proves that persuadable profiles are targetable while negative-uplift
profiles remain non-actionable.
