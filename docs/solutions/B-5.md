# B-5 Supplier Risk & Procurement Intelligence

Refs #1179 and catalogue epic #984. B-5 is a runnable solution module that
prioritizes supplier risk and procurement work while preserving the evidence
behind every flag. It composes native M-4 forecasting with M-1 risk prediction;
the policy consumes M-1's real `supplier_risk_results.risk_flags_*` output and
attaches the matching M-4 forecast interval and exception score.

The catalogue promotion condition remains recorded separately from engineering
readiness: offer the module when there is concentrated manufacturing demand and
external-data support is reusable across several modules.

## Data by role

| Role | Required | Contract |
|---|---:|---|
| entity | yes | Stable supplier key plus optional part, site, and contract identifiers. |
| label | yes | Supplier disruption or performance outcome observed after the prediction cutoff. |
| time | yes | Publication time for external signals, supplier-event time, and ordered delivery history. |
| feature | yes | Only pre-event delivery, quality, concentration, and external-risk fields. |
| owner | yes | Buyer or procurement team that receives review work. |
| evidence | yes | External source, publication cutoff, model reason codes, and forecast context. |
| cost | no | Mitigation cost for the policy budget and approval boundary. |

The decision snapshot must also carry the policy predicates
`procurement_eligible`, `external_data_current`, `evidence_complete`,
`supplier_closed`, and `sanctions_hold`. Missing required predicate evidence
blocks the action.

## Executable defaults

The policy has critical, watch, and monitor tiers. Critical suppliers can route
to a watch task at level 1, a procurement review at level 2, and an
approval-bounded mitigation task at levels 3–4. Watch suppliers receive the
bounded watch task; monitor suppliers receive `no_action`. The mitigation action
is A2 through 10,000 currency units and A1 above it. The complete policy also
sets a 50,000-unit budget, 12 lifetime actions, one action per seven-day window,
explicit eligibility and exclusion rules, and a kill switch.

Each tier has an independent permanent 10% holdout. The named outcome is
`disruption_avoided` per supplier over 60 days. Guardrails measure missing flag
evidence, stale external data, single-source exposure, mitigation spend, and
action execution. Thresholds and amounts are editable starter settings, not
calibrated supplier-risk advice or a return claim.

## Correctness checks

The bound correctness gate adds three B-5 checks:

1. `b5_point_in_time_external_data` requires every methodology source to be a
   snapshot at or before decision time. External evidence must name its source
   and use publication time as the snapshot boundary.
2. `b5_post_event_supplier_leakage` requires supplier history to stop at the
   disruption event and refuses any selected feature on the post-event
   blocklist.
3. `b5_flag_evidence` requires M-1 supplier-specific flag output, M-4 forecast
   context, external provenance fields, and model reason codes.

Each check has a refusal test for its bad case. Runtime joining also refuses a
score without exactly one snapshot supplier, a supplier without forecast
evidence, or a flagged supplier without its required provenance and reasons.

## Levels

| Level | Composition and action |
|---:|---|
| 1 | M-4 forecast evidence + M-1 supplier flags; publish bounded supplier watch tasks. |
| 2 | The same native stages; route owned procurement review tasks. |
| 3 | The same native stages; add mitigation tasks with cost approval. |
| 4 | The same native stages; route bounded procurement actions with the complete decision cell. |

Every level builds both registered methodology callbacks. The execution order is
M-4 then M-1 so forecast evidence is available when the supplier flag is turned
into a policy decision.

## Run it

Create a project, land a current supplier table and a frozen supplier-history
table, then call `create_solution` with `solution: "B-5"`, a level from 1–4,
M-1/M-4 column mappings, and the shared foundation:

```json
{
  "project": "supplier risk",
  "solution": "B-5",
  "level": 4,
  "sources": {
    "source": "supplier_data",
    "table": "suppliers",
    "M-1": {
      "entity_column": "entity_id",
      "label_column": "disruption",
      "feature_columns": ["late_delivery_rate", "concentration"]
    },
    "M-4": {
      "source": "supplier_data",
      "table": "supplier_history",
      "time_column": "day",
      "target_column": "late_delivery_rate",
      "series_column": "supplier_id",
      "horizon": 7,
      "seasonal_period": 7,
      "lags": [1, 7],
      "rolling_window": 7,
      "backtest_folds": 3
    }
  },
  "foundation": {
    "snapshot": {
      "database": "supplier_data",
      "source_table": "suppliers",
      "target_table": "supplier_risk_snapshot",
      "entity_column": "entity",
      "time_column": "external_observed_at",
      "as_of": "2026-09-01T00:00:00.000Z"
    },
    "dataset": {
      "entity_column": "entity_id",
      "label_column": "disruption",
      "feature_columns": ["late_delivery_rate", "concentration"]
    },
    "delivery": {
      "kind": "webhook",
      "endpoint": "https://procurement.example.test/tasks",
      "owner": "procurement-west"
    },
    "roi_model": {
      "value_per_outcome": 1000,
      "investment": 500,
      "currency": "USD"
    }
  }
}
```

Call `run_solution`, poll the returned Run, and read the policy, experiment,
monitor, ledger, and ROI records through their normal capabilities. Delivered
payloads contain supplier, part/site/contract context, the selected action and
decision cell, model score, external provenance, reason codes, and M-4 forecast
evidence. Holdouts remain non-actionable and are still recorded for measurement.

The `SolutionJourney.SupplierRiskProtectsHoldoutAndRecoversPlantedEffect` test
uses a synthetic point-in-time dataset, excludes a future supplier publication,
runs both methodologies, verifies evidence-bearing action payloads and protected
holdouts, records a planted 0.18 effect, and recovers that effect inside the ROI
confidence interval.
