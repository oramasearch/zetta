# v0.6.0

**Released:** 2026-11-16 · **Branch:** `dev` · **Previous:** [`v0.5.0`](https://github.com/oramasearch/zetta/releases/tag/v0.5.0) (2026-10-23)

`v0.5.0` was the security release. `v0.6.0` prepares the repository for its open-source release
(https://github.com/oramasearch/zetta/issues/1500), lands the first batch of fixes for the
pre-launch security review (https://github.com/oramasearch/zetta/issues/1388), and makes `score`
and `explain` work on segmentation models.

**This release was not planned with a release epic.** It carries the pull requests merged into `dev`
since `v0.5.0`. The epic https://github.com/oramasearch/zetta/issues/1500 is its tracking issue.

14 pull requests since `v0.5.0`:
- 4 security fixes;
- 1 build fix;
- 1 machine-learning fix;
- 5 release-readiness changes;
- 2 docs;
- 1 test.

The generated OpenAPI still has **190** `/v1` paths, and no capability was added or removed.

---

## Upgrade: read this first

- **A rolling upgrade is fine.** Nothing in this release changes replication, the peer protocol or
  a replicated record's shape. A `v0.5.0` node and a `v0.6.0` node can share a cluster.
- **Clerk now needs its authorized parties** (#1423, in #1503). A node with a Clerk issuer set
  accepts a Clerk token only when the token carries an integer `exp` and an `azp` listed in
  `ZETTA_CLERK_AUTHORIZED_PARTIES`, a comma-separated list of this node's Studio origins. **With an
  issuer and no list, every Clerk token is refused.** Bearer and session tokens are unaffected. No
  deployment sets a Clerk issuer today.
- **An inbox needs its own grant** (#1432, in #1505). A topic-prefix grant no longer reaches an
  inbox. A grant meant to open an inbox must name `inbox:<name>`.
- **The Studio web app is no longer in the repository** (#1527). `webapp/` was removed because it
  needs a rebuild from its source (#1526). A node started without `--webapp-dir` serves its built-in
  server-rendered UI at `/`, as before. A deployment that bakes `webapp/` into its image must stop
  copying it. The [`Dockerfile`](../../Dockerfile) added here handles both cases.

## Behaviour changes

- **Cookie routes check the session before reading the body** (#1395, in #1502).
  - A request with no session is answered without its body being read, and the connection is closed.
  - `POST /login`, `POST /session` and `POST /blob/delete` accept at most 64 KiB, and answer 413
    above that.
  - A blob upload checks `sql:write` before reading the file.
- **Redirects** (#1503):
  - A web run redirects only to a path on this origin (#1435).
  - The outbound HTTP client keeps secret headers across a redirect only when the scheme, host and
    port all match (#1429).
- **`list_datasets` lists only what the caller may read** (#1439, in #1503). The rule is the same as
  `system.datasets`: an administrator or the local session sees every dataset, and anyone else only
  the tables it holds `sql:read` on.
- **`storage_usage` shows a caller who is not an administrator only the buckets it may read** (#1430,
  in #1505). Per-kind totals are 0 for such a caller.
- **The web shell runs as the signed-in user** (#1434, in #1505): statements are authorized,
  executed and audited under the user, not the local session.
- **Parsers of untrusted input are bounded** (#1504):
  - Thrift metadata nests at most 64 levels (#1424).
  - Parquet counts are checked against the bytes present, and `read_parquet_rows` refuses a footer
    claiming more than 10,000,000 rows (#1425). **A Parquet file over 10 million rows uploaded
    through `add_dataset` is now refused.**
  - A tokenizer vocabulary whose ids run far past its size is refused (#1431).
  - A JPEG with a second frame is refused (#1418).
  - A Python pipeline expression nests at most 200 levels (#1427).

## Added

- **`score` and `explain` on segmentation (M-3) models** (#1497, in #1499).
  - `score` places each row in its nearest segment: `kind: "segmentation"` and `assignments`.
  - `explain` names the segment, the runner-up, and each column's contribution to the choice.
- **The image `Dockerfile` is in this repository** (#1530). It was in zetta-bridge. Build from the
  repository root: `docker buildx build --platform linux/amd64 -t <registry>/zetta:<version> .`.
  See [`docs/build.md`](../build.md#container-image-dockerfile-dockerignore).
- **Licensing** (#1524):
  - MIT `LICENSE` and `COPYRIGHT` (OramaSearch, Inc.).
  - `SPDX-License-Identifier: MIT` in every source file.
  - `THIRD_PARTY_LICENSES`, with 15 components and none incompatible with MIT.
  - An SBOM in SPDX and CycloneDX form, regenerated with `tools/sbom.py`.
  - `CONTRIBUTING.md`, with contributions under a copyright-assignment CLA (`CLA.md`).
  - `CODE_OF_CONDUCT.md`.
- **`SECURITY.md`** (#1506): report vulnerabilities privately to security@orama.com.

## Build and repository

- **Every `FetchContent` source is pinned by commit or hash** (#1508): SDL3, Dear ImGui,
  json-schema-validator and GoogleTest by commit, and the Boost archive by SHA-256.
- **Submodule remotes are https** (#1530). Every submodule repository is public, so an anonymous
  `git clone --recurse-submodules` works.
- **Schema `$id`s use one namespace**, `https://oramasearch.github.io/zetta/schemas/` (#1530). Nothing
  resolves or compares them.
- **Client and internal material is out of the tree** (#1523, #1525, #1527). The churn fixture's
  company is now the invented Contoso, and the demo data generators describe an invented business.
  The agent files are rewritten for the public repository, and finding ids and private links are
  removed. `docs/full-context.md` and `docs/architecture/code-audit.md` are gone.
- An object-log test's hooks now outlive the log they are installed in (#1491, in #1492). The v0.5.0
  notes record the image digest and the AddressSanitizer result (#1493).

## Known issues

**Security-relevant first.**

- The security fixes listed under *Not in this release* are not in this tag. They are tracked
  under https://github.com/oramasearch/zetta/issues/1388 and the epic #1500.
- The repository and the image `oramasearch/zetta` were made public on 2026-11-16, with the full
  history and every earlier image tag. GitHub private vulnerability reporting is on, and
  security@orama.com also takes reports.
- The new cookie-route bounds (#1531) and Parquet count bounds (#1532) have no tests of their own yet.
- `score` over a table on a multi-member cluster scores only the rows the answering member owns
  (#1533).
- **An intermittent segfault** in `Uc1Journey.ARunWithoutADatasetReadsItsPipelinesTable` (#1485).
- Latency-budget tests fail on a loaded host (#1256).
- `WHERE NOT (x = 5)` matches rows where `x` is null (#1473).
- Pending outbox and report rows from before `v0.5.0`'s outbox change are not delivered after the
  upgrade (#1474).
